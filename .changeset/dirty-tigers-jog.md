'@codama/renderers-rust': major

Generated events now expose `matches(data) -> bool` and `try_parse(data) -> Option<Result<Self, std::io::Error>>` in place of `from_bytes`. A discriminator mismatch is the common case when scanning a stream of program logs, and modelling it as an error forced callers to pattern match on an error message to tell "this is a different event" apart from "this event is corrupt". `try_parse` now returns `None` for data that is not this event and `Some(Err(_))` for data that matches the discriminator but fails to deserialize, so a batch can be collected with `filter_map` and `collect::<Result<_, _>>()`, and a single call can be propagated with `Option::transpose`. The program-level `identify_*_event` performs the shared Anchor CPI framing comparison once and rejects foreign data before testing any per-event discriminator. Framed events whose only discriminator is the shared CPI framing are now excluded from the generated event enum with a generation-time warning, since they cannot be told apart from one another, and two events that would render to the same file or struct name now fail generation with an actionable error instead of silently overwriting each other's files.

**Breaking:** after regenerating, replace `<Event>::from_bytes(data)?` with `<Event>::try_parse(data).transpose()?`, or with `<Event>::matches(data)` where only the discriminator test was wanted. Call sites that treated a discriminator mismatch as an `Err` with the message `invalid event discriminator` or `invalid event CPI framing` must instead treat `None` as the mismatch case; those messages are no longer produced by per-event parsing.
