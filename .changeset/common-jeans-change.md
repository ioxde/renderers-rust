'@codama/renderers-rust': major
---

Enums whose variants declare explicit discriminators now render them. `visitEnumType` dropped the discriminators entirely, so an enum declaring `Idle = 0`, `Active = 5`, `Closed = 9` rendered as three bare variants and Borsh encoded them by position as 0, 1 and 2 — the generated client disagreed with the program about every variant after the first gap. Once any variant carries a discriminator all of them are now emitted explicitly, because Codama fills an omitted discriminator from the variant's position whereas Rust infers it from the previous variant plus one, and those two rules only agree while the list is gapless. Discriminated enums also gain `#[borsh(use_discriminant = true)]` so Borsh honours the discriminants rather than the variant index, plus `#[repr(u8)]` when any variant carries data, which Rust requires for explicit discriminants on non-unit variants (E0732). An enum declaring a size other than `u8` now logs a warning, since Borsh always writes a one-byte discriminator and a wider declared size cannot be represented.

Numeric PDA seeds in generated instruction builders are now hashed as their endian-ordered bytes. The inline-PDA resolution behind the builders still sent `numberTypeNode` seeds through the catch-all that emits `.to_string().as_ref()`, so a `u64` seed was hashed as its decimal ASCII and the builder derived an address the program would never accept. Typed seeds now render as `&self.nonce.clone().to_le_bytes()`, following the node's declared endianness, and a seed fed by an omitted-default argument pins its inlined literal to that format — `&(42 as u32).to_le_bytes()` — because a bare integer literal gives Rust nothing to infer from. `shortU16` keeps the previous fallback, having no `to_le_bytes` method. This brings the builders in line with the standalone `pdas/*.rs` and account-page helpers, which already encoded numeric seeds this way.

Rendering a program with no address now fails with an explicit error instead of emitting a `programs.rs` containing `address!("")`, which fails Rust const-eval deep inside `five8_const` with nothing to point at the real cause. The error names the program and the IDL field expected to supply the address.

**Breaking:** after regenerating, any enum declaring explicit discriminators changes both its Rust representation and its Borsh encoding to match the program. Clients generated before this were self-consistent, so data they wrote will decode differently now; anything persisted by an older client needs re-reading against the corrected encoding. Instruction builders that derive a PDA from a numeric seed also produce a different — and now correct — address, so any address cached or hardcoded from the previous output is stale. IDLs carrying no program address, which previously generated uncompilable output, now fail generation outright.
